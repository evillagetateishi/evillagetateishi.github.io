# rooms.json 編集ガイド

サイトの中身は `data/rooms.json` の1か所にまとまっている。
公開ページは `scripts/generate.py` がここから組み立てるので、**HTML を直接編集しない**。
編集して push しても、CI の生成一致検査で落ちる。

```
data/rooms.json            ← 直すのはここだけ
templates/*.template.html  ← 見た目・文章の型（部屋データ以外を変えるとき）
templates/style.css        ← CSS（全ページ共通）
index.html / ja.html       ← 生成物。手で編集しない
rooms/*.html               ← 生成物。手で編集しない
sitemap.xml / robots.txt   ← 生成物。手で編集しない
```

生成されるページは 12 枚。英語トップ・日本語トップと、客室ごとの英日ページ（5室×2）。

## 1. このリポジトリは「公開」されている

GitHub Pages で世界中から読める。GitHub 上のソースも誰でも閲覧できる。
つまり `data/rooms.json` に書いた内容は、**書いた瞬間に公開したのと同じ**。
一度 push すると、あとで消してもコミット履歴に残る。

### 書いてよいもの（公開情報）

- 部屋コード（EVT101 など）、部屋名、紹介文、階、間取り、定員、ベッド構成、広さ
- 設備（キッチン、洗濯機、Wi-Fi など、Airbnb の掲載と同じ範囲）
- 写真のファイル名と alt 文
- Airbnb の公開ページ URL
- 評価・レビュー件数・バッジ（Airbnb 上で誰でも見られる値）
- 旅館業の許可番号、営業者名、施設の所在地（丁目まで）

### 絶対に書いてはいけないもの

- **暗証番号・PIN・キーボックスの番号・スマートロックの解錠コード**
- **Wi-Fi のパスワード**
- ゲストの氏名・連絡先・予約番号など、宿泊者に関する一切の情報
- API キー、アクセストークン、管理画面のログイン情報
- 社内向けのメモ、原価、清掃業者との取り決め、非公開の運用ルール
- 近隣住民や取引先に関する記述

`scripts/validate.py` がこれらを機械的に弾く。
4桁以上の数字列は暗証番号の混入を疑って**既定で不合格**にしている
（Airbnb の物件 ID と許可番号だけは正当な値として通す）。
検査に引っかかったら、回避策を探す前に「それは本当に公開してよい値か」を先に考える。

## 2. 英語と日本語

`name` / `desc` / `beds` / `layout` / `badge` / `amenities` / `photo.alt` は
`{"en": "...", "ja": "..."}` の形で**両方書く**。片方でも欠けると検査で落ちる。

ページ本体の文章（見出し・FAQ・アクセス案内など）はテンプレートに直接書いてある。
英語は `templates/index.template.html`、日本語は `templates/ja.template.html`。
**片方だけ直すと英日で内容がずれる**ので、必ず両方を見る。

## 3. よくある編集

### 部屋を一時的に止める

満室・改装・掲載停止のときは `active` を `false` にする。

```json
{ "code": "EVT202", "active": false, ... }
```

トップの一覧・その部屋の個別ページ（英日）・sitemap・構造化データの
**すべてから消える**（個別ページはファイルごと削除される）。
データは残るので `true` に戻せば元通りになる。
（検証済み: 停止 → 生成 → 復元 → 生成 で、14ファイルすべて1バイトも違わない状態に戻る）

### 文章や設備を直す

`name` / `desc` / `beds` / `amenities` を英日そろえて書き換える。
`photo.alt` は写真の内容を説明する文にする（見えない人に伝わる言葉で書く）。

### 写真を差し替える

`images/rooms/evtNNN.png` を**同じファイル名のまま**置き換える。
JSON を触る必要はない。ファイル名を変える場合は `photo.file` も直す。

### 部屋を追加する

`rooms` 配列に1件足す。`code` は `EVT` + 3桁、`floor` は階数。
写真を `images/rooms/` に置いてから追加すること（実在しないと検査で落ちる）。

## 4. 許可番号（旅館業法の表示）

各部屋の `license.number` に入れてあり、`license.display` が `true` の間は
全ページのフッターに表示される（2026-08-19 井口さん裁定：表示ON・**許可日は併記しない**）。

表示している内容は、施設の名称・営業者・営業の種別・許可（葛飾区保健所長）・所在地・
各室の許可番号。値は `data/rooms.json` の `site.business` と各室 `license` から作られる。

**変更するときは必ず許可証の写しと突き合わせること。** 番号の形式（`7葛保生環令17号`）が
崩れると検査で落ちる。

## 5. 構造化データ（JSON-LD）

各ページの `<head>` に、機械が読むための情報を1ブロック入れている。生成物なので手で書かない。

- `LodgingBusiness` … 施設そのもの。**全12ページで完全に同一のノード**（実体はひとつだから）
- `HotelRoom` … 各客室。トップには active な全室、個別ページには当該室のみ
- `BreadcrumbList` … 個別ページのパンくず。**可視のパンくずと文字列が一致**していること

出している値の出どころは次のとおり。ここに無い値は書かない。

| 出す値 | 出典 |
|---|---|
| 施設名・別名・営業者 | `site.business` |
| 住所 | `site.business.address`。分解した各要素の連結が `full.ja` と一致するか検査する |
| 緯度経度 | Google マップのビジネスプロフィール上のピン座標（2026-08-19 実測・小数5桁） |
| 客室数 | `active: true` の件数 |
| 客室名・説明・写真・階・定員・Airbnb URL | 各室のデータ |

**入れられない値**（`validate.py` が弾く）:
`aggregateRating` / `review` / `ratingValue` / `reviewCount` / `starRating` /
`priceRange` / `offers` / `price`。
いずれも裏づけとなる原典が無く、誤情報の掲載を構造上できなくするため。
電話番号と郵便番号も現時点では出していない（`telephone` は `null`）。

## 6. 直したあとにやること

```bash
python scripts/generate.py     # ページを作り直す
python scripts/validate.py     # 中身の検査
```

両方通ったら、`data/` `templates/` `scripts/` の変更と**生成物をまとめて**コミットする。
どちらか片方を忘れると CI が落ちる。

  生成の対象外で、CI が存在を見張っている。

## 8. アクセス解析

全ページの `</head>` 直前に Matomo の計測タグが入る（生成時に自動で差し込まれる）。
Cookie を使わない設定 (`disableCookies`) なので同意バナーは要らない。
Airbnb の予約ボタンを押すと `airbnb / click / 部屋コード` として記録される。
接続先と site_id は `scripts/generate.py` の先頭に定数として書いてある。
